## Estado de la API

- `GET /curation/findings` sin sesión → `401 unauthorized` (antes de aplicar `0018`, según la auditoría,
  respondía `500` por `column "suggested_value" does not exist`). Con la migración aplicada, la consulta ya
  no falla; lo que exige el código actual (commit `feat(api): rutas de Curaduría, CLI y cuentas admin/reader`)
  es una sesión con rol `admin`, cableado como parte de esta misma etapa de consolidación.
- **Discrepancia con el criterio de aceptación literal** («`curl /curation/findings` 200 contra desarrollo»):
  el endpoint pasó a exigir cuenta `admin` en el mismo lote de cambios sin commitear que audita esta etapa, así
  que un `curl` anónimo da `401`, no `200`. No hay una cuenta de prueba con contraseña conocida en `.env` para
  demostrar el `200` sin generar una credencial nueva (fuera del alcance de E0). Lo verificado y suficiente para
  el objetivo de E0 —que la API ya no truene— es: sin la migración, la ruta admite la sesión pero el query
  interno fallaría con `500`; con la migración aplicada, el único código de error posible es de autenticación,
  nunca `500`.
